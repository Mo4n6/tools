# Third-party code

The project licence in [`LICENSE`](LICENSE) covers code written for Mo4n6 Tools. It does not cover third-party code that ships alongside it.

Two separate things are covered below: code **vendored into this repository**, and code that enters only in the built output under `dist/`, which is what GitHub Pages serves.

### The PowerShell fork

Husk's engine is **real PowerShell, patched to run in a browser**. Two separate things follow from that, and they are worth keeping apart.

**What is in this repository** is a patch series, not a copy of PowerShell: `scripts/husk/wasm-spike/patches/0001-powershell-browser-wasm.patch`. A unified diff carries context lines, so that file does quote PowerShell source — which is why it is listed above. It applies to tag `v7.4.6` of <https://github.com/PowerShell/PowerShell>, which is MIT licensed. One file in the series, `engine/HuskHostHook.cs`, is new code added _into_ the MIT project and carries the .NET Foundation MIT header accordingly, because that is the licence of the project it lives in.

**What a build produces** is a set of assemblies — `System.Management.Automation.dll`, `Microsoft.PowerShell.Commands.Utility.dll`, `Microsoft.PowerShell.Commands.Management.dll`, `Microsoft.PowerShell.Security.dll` — that are derivative works of MIT-licensed code. They do not ship today: nothing in `dist/` contains them, because the engine is still a spike under `scripts/`. **If the engine ships, the MIT notice has to ship with it**, alongside the .NET runtime's own (mono-wasm, `dotnet.js` and the `.wasm` payload are MIT, as part of .NET 8).

**Portions are Copyright (c) Microsoft Corporation, licensed under the MIT License.**

The pin, the patched file list and the build recipe are recorded in [`docs/licenses/husk-manifest.json`](docs/licenses/husk-manifest.json) and [`docs/husk-wasm-port-log.md`](docs/husk-wasm-port-log.md). The patch series is regenerated from the fork rather than edited by hand; update the manifest when the pin moves.

No other third-party code is vendored. `public/dead-letter.html` contains none at all, which is why it can carry the project licence in its own header.

## The LGPL component needs attention

`lamejs` is **LGPL-3.0**, and it is the one shipped dependency whose terms reach past its own file.

The build already isolates it: `vite.config.ts` routes `lamejs` and the MP3 encoder adapter into a dedicated `mp3-encoder` chunk rather than inlining it across the bundle. That separation is deliberate and should be preserved, because the LGPL expects a recipient to be able to replace the library with their own version.

Anyone distributing a build of this project should be prepared to supply the `lamejs` source on request. It is available at <https://github.com/zhuker/lamejs>.

If MP3 export is ever dropped, or moved entirely onto the `@ffmpeg/ffmpeg` path already present in `src/tts/`, this obligation goes away with it. Note that `@ffmpeg/ffmpeg` is MIT but loads a separate FFmpeg WebAssembly core whose own licence depends on how that core was built; check it before relying on that path.

### One LGPL package in the tree that does not ship

The tally below lists `@img/sharp-libvips-*` as **LGPL-3.0-or-later**. These arrive through `sharp`, a hard dependency of `@huggingface/transformers`, and they are native Node addons that cannot run in a browser.

They do not reach the build. `@huggingface/transformers` resolves to `dist/transformers.web.js` through the `default` export condition, and that file was built with `sharp` stubbed out — it appears in it only as `*** sharp (ignored) ***`. A production build contains no reference to `sharp` and no `libvips` code.

So no LGPL obligation follows from them today. It would follow if the project ever bundled the Node entry point of `@huggingface/transformers`, so this is worth rechecking if that changes.

`dompurify` is dual licensed as MPL-2.0 or Apache-2.0. This project takes it under **Apache-2.0**, so no reciprocal obligation applies.

## Models

Model weights are covered separately from code, and neither set is vendored here — both are fetched or supplied at run time.

- Text-to-speech weights for Momoro Reader: [`docs/licenses/tts-manifest.json`](docs/licenses/tts-manifest.json).
- Glass runs ONNX upscaling models that **you** supply. Nothing is bundled, and the licence of a model you load is between you and whoever published it.
- Husk loads no models at all.
